\section{Research Objective}

The objective of this work is to develop and evaluate an evidence-based
calibration-adequacy framework that assesses, relative to a declared
calibration claim, whether a planned experimental protocol or an achieved
dataset provides the evidence required to support identifiable and practically
estimable calibration-model development, together with independent and
leakage-resistant evaluation of calibration performance over the intended
operating domain and conditions.

The framework defines sensor-agnostic evidence obligations and translates them
into sensor-, model-, and application-specific assessment tests. It reports
criterion-level outcomes and diagnostics rather than claiming unconditional
dataset sufficiency.

Dataset adequacy is not an absolute property. It must be evaluated relative to
a declared calibration claim, denoted by
\begin{equation}
    \mathcal{K}
    =
    \left(
        \mathbf{q},
        \mathbf{s},
        \Omega,
        \mathcal{C},
        \mathcal{M},
        \mathcal{P},
        \mathcal{G}
    \right),
    \label{eq:calibration-claim}
\end{equation}
where
\begin{description}[style=nextline,leftmargin=18mm]
    \item[$\mathbf{q}$] is the reference measurand to be estimated;
    \item[$\mathbf{s}$] is the vector of raw sensor indications used as
        calibration inputs;
    \item[$\Omega$] is the intended operating domain;
    \item[$\mathcal{C}$] is the set of relevant operating and experimental
        conditions;
    \item[$\mathcal{M}$] is the declared calibration-model class;
    \item[$\mathcal{P}$] is the set of required performance and uncertainty
        criteria; and
    \item[$\mathcal{G}$] is the intended generalization claim.
\end{description}

For an achieved dataset \(D\), the assessment target is therefore
\begin{equation}
    \operatorname{Adequacy}\left(D \mid \mathcal{K}\right).
    \label{eq:conditional-adequacy}
\end{equation}
The framework does not ask whether \(D\) is sufficient in isolation. It asks
which declared calibration claims \(D\) supports, which it contradicts, and
which remain indeterminate.

\subsection{Research sub-objectives}

\begin{enumerate}
    \item Derive the fundamental evidence obligations that apply across sensor
        calibration problems.
    \item Define how these obligations are operationalized for different sensor
        behaviours and classes of calibration models.
    \item Establish prospective and retrospective assessment procedures with
        explicit decision semantics.
    \item Evaluate the framework through controlled comparisons of calibration
        trajectories and a triaxial force-sensor case study.
\end{enumerate}

\section{Assessment Problem}

\subsection{Prospective assessment}

Before data collection, the framework evaluates whether a planned experimental
protocol \(\Pi\) is reasonably capable of producing the evidence required by
the declared calibration claim:
\begin{equation}
    A_{\mathrm{plan}}\left(\Pi \mid \mathcal{K}\right).
    \label{eq:prospective-assessment}
\end{equation}
This assessment may use the intended operating domain, commanded trajectories,
sampling procedure, reference system, repetitions, operating conditions, and
candidate model class. Because the achieved reference quantities and sensor
responses are not yet available, this assessment remains conditional and
cannot establish achieved dataset adequacy.

\subsection{Retrospective assessment}

After data collection, the framework evaluates whether the experiment actually
produced the required evidence:
\begin{equation}
    A_{\mathrm{data}}\left(D \mid \mathcal{K}\right).
    \label{eq:retrospective-assessment}
\end{equation}
This assessment must use the achieved, synchronized reference measurements and
raw sensor indications, together with the relevant run, time, and
operating-condition information.

\section{Working Definition of Adequacy}

A calibration dataset is considered adequate only when it provides sufficient
evidence that the calibration problem is:
\begin{enumerate}[label=(\Alph*)]
    \item \textbf{learnable}: the measurements contain enough information to
        distinguish the measurand components and estimate the declared model;
    \item \textbf{representative}: the intended operating domain and relevant
        experimental conditions are represented; and
    \item \textbf{validatable}: the experimental design supports an independent
        and unbiased evaluation of the resulting calibration.
\end{enumerate}

At the highest level, this working definition can be written as
\begin{equation}
    \operatorname{Adequate}\left(D \mid \mathcal{K}\right)
    =
    \operatorname{Learnable}\left(D \mid \mathcal{K}\right)
    \land
    \operatorname{Representative}\left(D \mid \mathcal{K}\right)
    \land
    \operatorname{Validatable}\left(D \mid \mathcal{K}\right).
    \label{eq:adequacy-components}
\end{equation}

Equations~\eqref{eq:conditional-adequacy}
and~\eqref{eq:adequacy-components} define the scope of the framework; the
individual criteria developed in the following sections will make these
concepts testable.

\section{Framework Architecture}

\subsection{Universal requirements}

The universal layer defines questions that every calibration study must
address, independently of sensor technology. These questions concern the
calibration claim, reference validity, informativeness, domain coverage,
experimental dependence, validation, performance, uncertainty, and
reproducibility.

\subsection{Sensor- and model-specific requirements}

The second layer translates the universal requirements into tests appropriate
to the sensor physics and calibration-model family. For example, an affine
model may require design-matrix rank and conditioning tests, whereas a dynamic
or hysteretic model requires evidence about temporal excitation and loading
history.

\section{Decision Semantics}

Each requirement shall produce an evidence-backed result rather than an
unsupported aggregate score:
\begin{description}[leftmargin=35mm,style=sameline]
    \item[\textsc{Pass}] the available evidence satisfies the declared
        requirement;
    \item[\textsc{Fail}] the available evidence contradicts or does not satisfy
        the requirement;
    \item[\textsc{Indeterminate}] the required evidence is missing or
        insufficient for a defensible decision;
    \item[\textsc{Not Applicable}] the requirement does not apply under the
        declared calibration claim.
\end{description}

For \(J\) framework requirements, either assessment may be represented as
\begin{equation}
    A(\,\cdot\mid\mathcal{K})
    \longrightarrow
    \left\{
        \textsc{Pass},
        \textsc{Fail},
        \textsc{Indeterminate},
        \textsc{Not Applicable}
    \right\}^{J}
    +
    \text{diagnostic evidence}.
    \label{eq:assessment-output}
\end{equation}

Every result should report the evaluated question, required evidence,
assumptions, assessment method, result, justification, consequence for the
calibration claim, and any recommended corrective action.

\section{Scope of the Claims}

The framework is intended to provide a transparent and reproducible method for
determining what the available evidence supports, what it contradicts, and what
remains indeterminate. It does not claim to:
\begin{itemize}
    \item prove unconditional sufficiency from a finite dataset;
    \item prescribe a single numerical threshold suitable for every sensor;
    \item guarantee that a particular model will achieve a required error;
    \item identify a universally optimal calibration trajectory; or
    \item assume that any named trajectory family is adequate by construction.
\end{itemize}

\section{Research Questions}

\begin{enumerate}
    \item Which calibration-dataset adequacy requirements are universal?
    \item Which requirements depend on the sensor physics or calibration-model
        class?
    \item Which requirements can be assessed before data collection, and which
        require achieved sensor and reference measurements?
    \item How should insufficient or missing evidence be represented?
    \item How can competing calibration trajectories be compared under a common
        experimental budget?
    \item Can the framework predict calibration viability in a real triaxial
        sensor case study?
\end{enumerate}
