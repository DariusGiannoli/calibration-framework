\section{Central Research Question}

\begin{quote}
Given a calibration objective, how can we determine whether an experimental
protocol or dataset provides enough appropriate evidence to develop and
evaluate a viable sensor calibration?
\end{quote}

\section{Definition of Adequacy}

Neither an experimental protocol nor an acquired dataset can be considered
adequate in isolation. Adequacy must be assessed relative to a declared
calibration task:
\begin{equation}
    \mathcal{T}
    =
    \left(
        \mathbf{s},
        \mathbf{q},
        \Omega,
        \mathcal{C},
        \mathcal{M},
        \mathcal{P},
        \mathcal{G}
    \right),
\end{equation}
where:
\begin{itemize}
    \item $\mathbf{s}$ is the vector of raw sensor signals used as calibration
        inputs;
    \item $\mathbf{q}$ is the reference measurand that the calibration must
        estimate;
    \item $\Omega$ is the intended operating domain;
    \item $\mathcal{C}$ is the set of relevant operating conditions;
    \item $\mathcal{M}$ is the calibration model or candidate model family;
    \item $\mathcal{P}$ is the required performance and uncertainty;
    \item $\mathcal{G}$ is the intended generalization claim.
\end{itemize}

For an acquired dataset $D$, achieved-dataset adequacy is therefore
conditional:
\begin{equation}
    \operatorname{Adequacy}_{\mathrm{ach}}
    \left(D \mid \mathcal{T}\right).
\end{equation}

A calibration protocol is represented by
\begin{equation}
    \Pi_{\boldsymbol{\lambda}}
    =
    \left\{
        \mathbf{u}_{r}(t;\boldsymbol{\lambda}_{r}),
        \mathbf{z}_{r}(t;\boldsymbol{\lambda}_{r})
        :
        r\in\mathcal{R}_{\Pi}
    \right\},
\end{equation}
where $\mathbf{u}_{r}$ is the rig command for run $r$,
$\mathbf{z}_{r}$ is its planned operating-condition schedule,
$\boldsymbol{\lambda}_{r}$ contains the trajectory parameters, and
$\mathcal{R}_{\Pi}$ is the planned set of experimental runs. The symbol
$\boldsymbol{\lambda}$ is reserved for protocol parameters and is distinct
from the calibration-model parameters.

Prospective protocol adequacy is also conditional:
\begin{equation}
    \operatorname{Adequacy}_{\mathrm{plan}}
    \left(
        \Pi_{\boldsymbol{\lambda}}
        \mid
        \mathcal{T},
        \mathcal{H}
    \right),
\end{equation}
where $\mathcal{H}$ contains the declared rig model, sensor-response prior,
physical constraints, and uncertainty assumptions used to predict what the
protocol will achieve. Consequently, a prospective conclusion is a
model-conditional design statement. It is not evidence that the final
acquisition or calibration has already succeeded.

\section{Universal Criteria}

The criteria below define universal scientific obligations. Their primary
formulation states what must be established using achieved evidence. The
section on prospective protocol adequacy defines how the same obligations are
used before acquisition without confusing commanded or model-predicted
evidence with achieved measurements.

\subsection{Criterion D0: Calibration Claim Completeness}

D0 is a precondition for both prospective protocol assessment and achieved
dataset assessment. Each component of $\mathcal{T}$ must be specified with
enough detail to evaluate the applicable criteria. In particular, the claimed
domains, model family, performance requirements, and generalization target
cannot remain implicit.

Let $\operatorname{Specified}(x)$ indicate that $x$ is defined at the level
required for assessment. D0 is satisfied when
\begin{equation}
    \bigwedge_{
        x\in
        \left\{
            \mathbf{s},
            \mathbf{q},
            \Omega,
            \mathcal{C},
            \mathcal{M},
            \mathcal{P},
            \mathcal{G}
        \right\}
    }
    \operatorname{Specified}(x)
\end{equation}
is true. For a prospective assessment, D0 additionally requires
\begin{equation}
    \bigwedge_{
        x\in
        \left\{
            \mathcal{F},
            \Lambda,
            \mathcal{H}
        \right\}
    }
    \operatorname{Specified}(x),
\end{equation}
where $\mathcal{F}$ is the declared set of candidate protocol families,
$\Lambda$ is its parameter search space, and $\mathcal{H}$ is the planning
description used to predict execution and sensor response. If a required
component is missing, the affected criteria and the phase-qualified overall
assessment are \textsc{Indeterminate}, rather than being assigned assumed
values.

\subsection{Criterion D1: Measurement and Reference Validity}

The dataset must contain trustworthy pairs of sensor readings and reference
measurements. For each sample $i$,
\begin{equation}
    \left(\mathbf{s}_i,\mathbf{q}_i\right)
\end{equation}
must represent the same physical state.

The measurements are considered valid when:
\begin{equation}
    |\Delta t_i| \leq \Delta t_{\max},
    \qquad
    \mathbf{s}_i \in \mathcal{S}_{\mathrm{valid}},
    \qquad
    \mathbf{q}_i \in \mathcal{Q}_{\mathrm{valid}},
    \qquad
    U_{\mathrm{ref}} \leq U_{\mathrm{ref}}^{\max},
\end{equation}
where $\Delta t_i$ is the synchronization error,
$\mathcal{S}_{\mathrm{valid}}$ and $\mathcal{Q}_{\mathrm{valid}}$ are the valid
measurement ranges, and $U_{\mathrm{ref}}$ is the reference-sensor uncertainty.

The units, axis directions, coordinate transformations, acquisition bandwidth,
and sampling process must also be known whenever they affect the declared
calibration task. Missing values, exclusions, clipping, saturation, and other
invalid observations must be detected and handled using a documented rule.
Excluding invalid observations does not automatically satisfy D1: the
remaining dataset and the exclusion mechanism must still support the declared
claim.

D1 is \textsc{Pass} when the retained sensor--reference pairs are trustworthy
and the required measurement evidence is available. It is \textsc{Fail} when
a known measurement defect invalidates the intended use, and
\textsc{Indeterminate} when essential validity evidence is unavailable.

\subsection{Criterion D2: Claimed-Domain Coverage}

D2 determines whether the achieved dataset represents the domain covered by
the calibration claim. The complete claim domain combines the measurand domain
and the relevant operating conditions:
\begin{equation}
    \mathcal{X}
    =
    \Omega\times\mathcal{C}.
\end{equation}

Let $\mathbf{z}_i\in\mathcal{C}$ denote the operating conditions associated
with observation $i$. The achieved support is
\begin{equation}
    \mathcal{S}_D
    =
    \left\{
        \left(\mathbf{q}_i,\mathbf{z}_i\right)
        :
        i=1,\ldots,N
    \right\}
    \subseteq
    \mathcal{X}.
\end{equation}

The universal requirement is that every part of the claimed domain is either
supported by the achieved data or explicitly excluded from the calibration
claim:
\begin{equation}
    \mathcal{X}_{\mathrm{claim}}
    \subseteq
    \mathcal{X}_{\mathrm{supported}}
    \cup
    \mathcal{X}_{\mathrm{excluded}}.
\end{equation}
Marginal coverage of each variable is not sufficient when their joint
combinations are part of the claim. Commanded trajectories provide prospective
evidence only; retrospective D2 assessment uses achieved reference
measurements and recorded conditions.

For a continuous domain equipped with an appropriate normalized distance
$d_{\mathcal{X}}$, one possible coverage diagnostic is the fill distance
\begin{equation}
    h(D,\mathcal{X})
    =
    \sup_{\mathbf{x}\in\mathcal{X}}
    \min_{\mathbf{x}_i\in\mathcal{S}_D}
    d_{\mathcal{X}}(\mathbf{x},\mathbf{x}_i).
\end{equation}
For categorical or mixed domains, coverage is instead evaluated within the
declared condition strata. The distance, partition, resolution, and threshold
are application-dependent tests rather than universal constants.

D2 is \textsc{Pass} when the supported and excluded regions justify the full
claim, \textsc{Fail} when a claimed region is known to be unsupported, and
\textsc{Indeterminate} when the domain, achieved conditions, or required
coverage resolution has not been declared.

\subsection{Criterion D3: Informativeness and Identifiability}

Informativeness determines whether the dataset contains enough independent
variation to distinguish the relationships required by the declared model
family $\mathcal{M}$. The universal obligation is predictive
distinguishability: models that are observationally indistinguishable on the
dataset must not imply materially different predictions within the claimed
domain.

For two models $f_{\boldsymbol{\theta}_1}$ and
$f_{\boldsymbol{\theta}_2}$, this obligation can be expressed as
\begin{equation}
    \left[
        f_{\boldsymbol{\theta}_1}(\mathbf{s}_i)
        =
        f_{\boldsymbol{\theta}_2}(\mathbf{s}_i),
        \quad
        i=1,\ldots,N
    \right]
    \Longrightarrow
    f_{\boldsymbol{\theta}_1}
    \sim_{\mathcal{X}}
    f_{\boldsymbol{\theta}_2},
\end{equation}
where $\sim_{\mathcal{X}}$ means equivalence to the resolution required by the
calibration claim over $\mathcal{X}$. The dataset must also avoid confounding
the measurand with operating condition, run, time, or protocol whenever their
effects must be separated.

For an identifiable parametric calibration model, a local model-specific test
uses the sensitivity matrix. Given
\begin{equation}
    \widehat{\mathbf{q}}
    =
    f_{\boldsymbol{\theta}}(\mathbf{s}),
    \qquad
    \boldsymbol{\theta}\in\mathbb{R}^{p},
\end{equation}
define the dataset sensitivity matrix as
\begin{equation}
    \mathbf{J}_D
    =
    \begin{bmatrix}
        \dfrac{\partial f_{\boldsymbol{\theta}}(\mathbf{s}_1)}
              {\partial\boldsymbol{\theta}^{\mathsf{T}}}
        \\
        \vdots
        \\
        \dfrac{\partial f_{\boldsymbol{\theta}}(\mathbf{s}_N)}
              {\partial\boldsymbol{\theta}^{\mathsf{T}}}
    \end{bmatrix}.
\end{equation}

The model parameters are locally identifiable when
\begin{equation}
    \operatorname{rank}(\mathbf{J}_D)=p.
\end{equation}

Practical identifiability is evaluated using the condition number
\begin{equation}
    \kappa(\mathbf{J}_D)
    =
    \frac{\sigma_{\max}(\mathbf{J}_D)}
         {\sigma_{\min}(\mathbf{J}_D)}.
\end{equation}

The dataset satisfies D3 when
\begin{equation}
    \operatorname{rank}(\mathbf{J}_D)=p,
    \qquad
    \kappa(\mathbf{J}_D)\leq\kappa_{\max},
\end{equation}
where $\kappa_{\max}$ is the maximum acceptable condition number after
appropriate normalization of the model variables.

The rank and condition-number test is not universal to every model family.
Linear models use design-matrix rank, nonlinear parametric models may use
local sensitivities, dynamic models require excitation across relevant
frequencies and histories, and over-parameterized predictive models require
model-specific evidence. D3 is \textsc{Pass} when the declared model
relationships are distinguishable with adequate practical conditioning,
\textsc{Fail} when a known ambiguity or confounding remains, and
\textsc{Indeterminate} when the model-dependent test or its threshold is
undefined.

\subsection{Criterion D4: Independent Replication and Dependence}

This criterion determines whether the dataset contains sufficient independent
experimental repetitions and whether temporal dependence between samples is
properly recognized.

Let the dataset be divided into $R$ independent experimental runs:
\begin{equation}
    D
    =
    \bigcup_{r=1}^{R}D_r,
\end{equation}
where $D_r$ contains the observations collected during run $r$.

Samples collected within the same continuous run may be temporally correlated.
Therefore, the number of recorded samples is not necessarily the number of
independent observations. The independent unit must be defined from the
generalization claim $\mathcal{G}$, and repetitions must independently repeat
the relevant initialization and experimental procedure.

For a stationary time series, one possible dependence diagnostic is the
approximate effective sample size
\begin{equation}
    N_{\mathrm{eff},v}
    =
    \sum_{r=1}^{R}
    \frac{N_r}
    {
        1
        +
        2\sum_{k=1}^{K_v}\rho_{r,v}(k)
    },
\end{equation}
where $N_r$ is the number of samples in run $r$,
$\rho_{r,v}(k)$ is the lag-$k$ autocorrelation, and $K_v$ is the maximum
relevant correlation lag.

For this diagnostic, a possible application-specific requirement is
\begin{equation}
    R\geq R_{\min},
    \qquad
    \min_{v\in\mathcal{V}}N_{\mathrm{eff},v}
    \geq
    N_{\mathrm{eff}}^{\min},
\end{equation}
where $\mathcal{V}$ is the set of signals relevant to the calibration.

The effective-sample-size expression is not a universal estimator: the
appropriate dependence model depends on the signals, sampling process, and
experimental design. D4 is \textsc{Pass} when the required independent units,
repetitions, and dependence evidence are available, \textsc{Fail} when
recorded samples are incorrectly treated as independent or required
repetitions are absent, and \textsc{Indeterminate} when the independent unit or
minimum evidence has not been declared.

\subsection{Criterion D5: Leakage-Resistant Validation}

This criterion determines whether calibration performance is evaluated using
data that are independent of model development and consistent with the declared
generalization claim $\mathcal{G}$.

The dataset is divided into
\begin{equation}
    D
    =
    D_{\mathrm{dev}}
    \;\dot{\cup}\;
    D_{\mathrm{test}},
\end{equation}
where $D_{\mathrm{dev}}$ is used for preprocessing, model fitting, and model
selection, while $D_{\mathrm{test}}$ is used only for final performance
evaluation.

When preprocessing or model choices are data-dependent, development data may
be divided internally as
\begin{equation}
    D_{\mathrm{dev}}
    =
    D_{\mathrm{fit}}
    \;\dot{\cup}\;
    D_{\mathrm{select}},
\end{equation}
or evaluated through an equivalent group-aware resampling procedure. The final
test data remain outside all such decisions.

Let $g_i$ identify the independent experimental unit required by the
generalization claim, such as a run, operating condition, or physical sensor
unit. Define
\begin{equation}
    \mathcal{G}(D')
    =
    \left\{
        g_i :
        i\in D'
    \right\}.
\end{equation}

The development and test sets must satisfy
\begin{equation}
    \mathcal{G}(D_{\mathrm{dev}})
    \cap
    \mathcal{G}(D_{\mathrm{test}})
    =
    \varnothing.
\end{equation}

All data-dependent operations must be determined using only
$D_{\mathrm{dev}}$. If
\begin{equation}
    \widehat{\boldsymbol{\theta}}
    =
    \operatorname{Fit}(D_{\mathrm{dev}}),
\end{equation}
then the reported performance must be calculated as
\begin{equation}
    \widehat{\mathcal{P}}_{\mathrm{test}}
    =
    \operatorname{Evaluate}
    \left(
        f_{\widehat{\boldsymbol{\theta}}},
        D_{\mathrm{test}}
    \right).
\end{equation}

The dataset satisfies D5 when the development and test units are disjoint, the
test set was not used during model development, and the number of independent
test units satisfies
\begin{equation}
    \left|
        \mathcal{G}(D_{\mathrm{test}})
    \right|
    \geq
    G_{\mathrm{test}}^{\min}.
\end{equation}

D5 is \textsc{Pass} when the partition unit matches $\mathcal{G}$, all
data-dependent decisions are isolated from the final test units, and the test
evidence is sufficient. It is \textsc{Fail} when information crosses the
development--test boundary, and \textsc{Indeterminate} when partition
provenance or the relevant generalization unit is unknown.

\subsection{Criterion D6: Performance Evaluation and Uncertainty}

This criterion determines whether the independent test data allow calibration
performance and uncertainty to be estimated precisely enough for comparison
with the declared requirements $\mathcal{P}$.

For each test sample $i$, the calibration error is
\begin{equation}
    \mathbf{e}_i
    =
    \widehat{\mathbf{q}}_i-\mathbf{q}_i.
\end{equation}
The uncertainty $U(\widehat{\mathbf{q}}_i)$ associated with an individual
calibrated estimate is distinct from uncertainty in a reported aggregate
performance metric. Both must be addressed when required by $\mathcal{P}$.

Let $m_\ell$ be a required performance metric. Its estimate on the independent
test data is
\begin{equation}
    \widehat{m}_\ell
    =
    m_\ell(D_{\mathrm{test}}).
\end{equation}

The uncertainty of the metric is represented by a confidence interval
\begin{equation}
    CI_\ell
    =
    \left[
        m_\ell^{-},
        m_\ell^{+}
    \right],
\end{equation}
with half-width
\begin{equation}
    w_\ell
    =
    \frac{
        m_\ell^{+}-m_\ell^{-}
    }{2}.
\end{equation}

The dataset provides sufficiently precise performance evidence when
\begin{equation}
    w_\ell
    \leq
    w_\ell^{\max},
\end{equation}
where $w_\ell^{\max}$ is the maximum acceptable uncertainty in the reported
metric.

Global metrics can hide local failure. If the claim domain is divided into
relevant regions $\{\mathcal{B}_b\}_{b=1}^{B}$, regional performance is
\begin{equation}
    \widehat{m}_{\ell,b}
    =
    m_\ell
    \left(
        \left\{
            i\in D_{\mathrm{test}}
            :
            \left(\mathbf{q}_i,\mathbf{z}_i\right)
            \in\mathcal{B}_b
        \right\}
    \right).
\end{equation}
The regions and required precision must be declared before inspecting final
test results.

For a metric where smaller values indicate better performance, the calibrated
model satisfies the corresponding requirement when
\begin{equation}
    m_\ell^{+}
    \leq
    \tau_\ell,
\end{equation}
where $\tau_\ell$ is the declared acceptance threshold. Dataset adequacy and
calibration acceptance are reported separately: a sufficiently precise result
showing that the model fails a requirement does not make the dataset
inadequate. D6 is \textsc{Pass} when test performance and required uncertainty
quantities can be estimated with the declared precision, \textsc{Fail} when
the independent test evidence is known to be insufficiently precise, and
\textsc{Indeterminate} when metrics, thresholds, uncertainty methods, or
precision requirements are undefined. Whether the calibrated model satisfies
$\mathcal{P}$ is a separate acceptance result.

\subsection{Criterion D7: Reproducibility and Provenance}

D7 determines whether the dataset assessment can be independently reproduced
and audited. The evidence package is represented as
\begin{equation}
    \mathcal{E}
    =
    \left(
        D_{\mathrm{raw}},
        H,
        M_{\mathrm{acq}},
        \mathcal{T},
        C_{\mathrm{criteria}},
        C_{\mathrm{preprocess}},
        C_{\mathrm{software}},
        S_{\mathrm{partition}},
        S_{\mathrm{random}},
        R_{\mathrm{evidence}}
    \right),
\end{equation}
where $H$ contains integrity hashes, $M_{\mathrm{acq}}$ contains acquisition
and instrument metadata, the $C$ terms contain configurations and versions,
the $S$ terms record partitions and random seeds, and
$R_{\mathrm{evidence}}$ contains the generated criterion results.

Every material input must be uniquely identified. For a file $f$, an integrity
record may use
\begin{equation}
    H_f
    =
    \operatorname{SHA256}(f).
\end{equation}
Another evaluator using the same evidence package should reproduce the
criterion outcomes and numerical results within declared numerical tolerance.

D7 is \textsc{Pass} when the raw evidence, provenance, configurations, and
software state are sufficient to reproduce D0--D6. It is \textsc{Fail} when a
known loss or undocumented transformation prevents reproduction, and
\textsc{Indeterminate} when required provenance is unavailable.

\subsection{Achieved-Dataset Decision Semantics}

Each applicable dataset criterion returns one of
\begin{equation}
    A_k^{\mathrm{ach}}
    \in
    \left\{
        \textsc{Pass},
        \textsc{Fail},
        \textsc{Indeterminate},
        \textsc{Not Applicable}
    \right\},
    \qquad
    k=1,\ldots,7.
\end{equation}

If D0 is incomplete, the overall result is \textsc{Indeterminate}. Otherwise,
for the required criteria, the overall dataset assessment is
\begin{equation}
    A_{\mathrm{ach}}
    \left(
        D_{\mathrm{ach}}
        \mid
        \mathcal{T}
    \right)
    =
    \begin{cases}
        \textsc{Fail},
            & \text{if at least one required criterion fails},\\
        \textsc{Indeterminate},
            & \text{if none fails and at least one is indeterminate},\\
        \textsc{Pass},
            & \text{if every required criterion passes}.
    \end{cases}
\end{equation}
Every result must retain criterion-level evidence; the overall result is not a
replacement for the individual conclusions. Calibration acceptance under
$\mathcal{P}$ is reported separately from dataset adequacy. A criterion may be
\textsc{Not Applicable} only when the declared task makes its underlying
obligation irrelevant; it is then excluded from the overall aggregation.

\section{Prospective Protocol Adequacy and Design}

\subsection{Evidence Levels}

The framework distinguishes commanded, predicted, and achieved evidence. The
commanded protocol produces
\begin{equation}
    D_{\mathrm{cmd}}
    \left(
        \boldsymbol{\lambda}
    \right)
    =
    \left\{
        t_i,
        r_i,
        \mathbf{u}_i
        \left(
            \boldsymbol{\lambda}
        \right),
        \mathbf{z}_i
        \left(
            \boldsymbol{\lambda}
        \right)
    \right\}_{i=1}^{N_{\mathrm{cmd}}}.
\end{equation}
Commanded evidence establishes what was requested from the rig. It does not,
by itself, establish which reference forces or sensor signals will be
achieved.

Let the planning description be
\begin{equation}
    \mathcal{H}
    =
    \left(
        g_{\boldsymbol{\eta}},
        h_{\boldsymbol{\eta}},
        \mathcal{K},
        \Xi
    \right),
\end{equation}
where:
\begin{itemize}
    \item $g_{\boldsymbol{\eta}}$ is a rig model that maps commands and
        conditions to predicted reference measurands;
    \item $h_{\boldsymbol{\eta}}$ is a sensor-response prior that maps
        predicted measurands and conditions to predicted raw sensor signals;
    \item $\mathcal{K}$ is the set of physical, safety, bandwidth, boundary,
        and execution constraints; and
    \item $\Xi$ is the declared set or distribution of plausible model,
        tracking, noise, and nuisance-parameter scenarios
        $\boldsymbol{\eta}$.
\end{itemize}
The models may depend on state or history when the declared task requires it.
For scenario $\boldsymbol{\eta}\in\Xi$,
\begin{align}
    \mathbf{q}^{\mathrm{pred}}_i
    &=
    g_{\boldsymbol{\eta}}
    \left(
        \mathbf{u}_i,
        \mathbf{z}_i,
        \text{history}_i
    \right),\\
    \mathbf{s}^{\mathrm{pred}}_i
    &=
    h_{\boldsymbol{\eta}}
    \left(
        \mathbf{q}^{\mathrm{pred}}_i,
        \mathbf{z}_i,
        \text{history}_i
    \right).
\end{align}
These quantities form the predicted dataset
\begin{equation}
    D_{\mathrm{pred}}
    \left(
        \boldsymbol{\lambda},
        \boldsymbol{\eta}
    \right)
    =
    \left\{
        t_i,
        r_i,
        \mathbf{s}^{\mathrm{pred}}_i,
        \mathbf{q}^{\mathrm{pred}}_i,
        \mathbf{z}_i
    \right\}_{i=1}^{N_{\mathrm{pred}}}.
\end{equation}

After execution, the achieved dataset is
\begin{equation}
    D_{\mathrm{ach}}
    =
    \left\{
        t_i^s,
        t_i^{\mathrm{ref}},
        r_i,
        \mathbf{s}_i,
        \mathbf{q}^{\mathrm{ref}}_i,
        \mathbf{z}_i
    \right\}_{i=1}^{N_{\mathrm{ach}}}.
\end{equation}
The transition
\begin{equation}
    D_{\mathrm{cmd}}
    \longrightarrow
    D_{\mathrm{pred}}
    \longrightarrow
    D_{\mathrm{ach}}
\end{equation}
must remain visible in all reports. A commanded value must not be silently
substituted for a predicted or achieved value.

\subsection{Use of the Universal Criteria in Both Phases}

The identifiers D0--D7 denote universal scientific obligations. Each
obligation may have a prospective test, an achieved-data test, or both. The
evidence phase and evidence source must accompany every criterion result.

\begin{description}[style=nextline]
    \item[D0---Claim completeness.]
    Before acquisition, D0 checks that the calibration task, protocol-design
    question, parameter search space, planning models, constraints, thresholds,
    generalization claim, and uncertainty scenarios are sufficiently declared.
    After acquisition, it checks the frozen calibration claim used for the
    final assessment.

    \item[D1---Measurement and execution validity.]
    Prospectively, D1 contributes capability and executability constraints:
    instrument ranges, reference capability, frame geometry, synchronization,
    bandwidth, sampling, and rig limits must be compatible with the proposed
    protocol. This is not proof that future observations will be valid.
    Retrospective D1 evaluates the actual retained sensor--reference pairs.

    \item[D2---Claimed-domain coverage.]
    Prospectively, the coverage method is applied to
    $\mathbf{q}^{\mathrm{pred}}$ and the planned conditions for every required
    scenario. Commanded measurands may be used only when a declared rig
    argument justifies their equivalence to achieved measurands.
    Retrospectively, D2 is applied to achieved reference measurements and
    recorded conditions.

    \item[D3---Informativeness and identifiability.]
    Prospectively, the model-specific information test is applied to predicted
    sensor signals, a declared sensitivity model, or a justified structural
    proxy. Retrospectively, the same obligation is tested using achieved sensor
    inputs. The proxy, assumptions, and loss of information relative to the
    achieved test must be reported.

    \item[D4---Independent replication and dependence.]
    Prospectively, D4 checks whether the protocol schedules the required
    separate acquisitions, configurations, repetitions, initialization, and
    zeroing operations. Dependence and effective sample size may be predicted
    only under a declared stochastic or dynamic model. Retrospectively, they
    are estimated from achieved runs.

    \item[D5---Leakage-resistant validation.]
    Prospectively, D5 checks that a complete run-level development/test
    allocation is possible and can be frozen before final evaluation.
    Retrospectively, it verifies the realized partition and its provenance.

    \item[D6---Performance and uncertainty evidence.]
    Prospectively, simulation or pilot-based uncertainty models may estimate
    the number and allocation of independent test runs needed to achieve the
    declared metric precision. Predicted calibration performance remains
    conditional on the assumed rig, sensor, noise, and model descriptions.
    Retrospectively, D6 evaluates held-out performance and uncertainty.

    \item[D7---Reproducibility and provenance.]
    Prospectively, D7 requires versioned task, protocol, model, constraint,
    parameter-bound, optimizer, seed, and command-file records.
    Retrospectively, it additionally requires immutable raw data and
    reproduction of the achieved assessment.
\end{description}

\subsection{Universal and Specific Responsibilities}

The framework is device-agnostic because the universal layer specifies
obligations and interfaces rather than a particular trajectory, sensor, or
rig. Its responsibilities are:
\begin{itemize}
    \item define the task, evidence levels, criterion semantics, and required
        provenance;
    \item calculate joint-domain coverage from supplied points and a declared
        domain;
    \item request a model-specific information measure and compare it with
        declared requirements;
    \item enforce replication, validation, and uncertainty obligations;
    \item aggregate criterion results without hiding missing evidence; and
    \item formulate protocol selection as a constrained, auditable search.
\end{itemize}

Application-specific components satisfy the following interfaces:
\begin{description}[style=nextline]
    \item[Protocol-family interface.]
    Defines
    $\mathbf{u}(t;\boldsymbol{\lambda})$, its parameter bounds, derivatives,
    duration, boundary conditions, and discrete run choices. Lissajous,
    spiral, waypoint, random, factorial, and optimized designs are alternative
    implementations of this interface.

    \item[Rig interface.]
    Provides $g_{\boldsymbol{\eta}}$, rig states, feasible commands, tracking
    behavior, and physical constraints. The universal layer does not assume
    that a force command is achieved exactly.

    \item[Sensor interface.]
    Provides $h_{\boldsymbol{\eta}}$, valid ranges, saturation behavior, noise,
    nuisance effects, and uncertainty scenarios. A planning prior is not
    treated as final calibration evidence.

    \item[Calibration-model interface.]
    Constructs the feature matrix, sensitivity matrix, Jacobian, Fisher
    information, or other model-appropriate informativeness object. For an
    affine model this may be a normalized design matrix; for nonlinear or
    dynamic models the method is different.

    \item[Optimizer interface.]
    Searches the declared protocol parameter space and returns feasible
    candidates, objective values, constraint margins, convergence information,
    and any valid infeasibility bound.
\end{description}

\subsection{Robust Feasibility and Parameter Selection}

Let $\Lambda_{\mathrm{safe}}(\mathcal{F},\mathcal{H})$ be the allowed parameter
space for a declared set of trajectory families $\mathcal{F}$ after applying
the deterministic constraints in $\mathcal{K}$. Let
$h_{\mathrm{plan}}(\boldsymbol{\lambda},\boldsymbol{\eta})$ be the D2 coverage
measure calculated from $D_{\mathrm{pred}}$, and let
$I_{\mathcal{M}}(\boldsymbol{\lambda},\boldsymbol{\eta})$ be the
model-specific D3 information result.

A robustly feasible protocol parameter vector satisfies
\begin{equation}
    \boldsymbol{\lambda}
    \in
    \Lambda_{\mathrm{safe}}
    \quad\text{and}\quad
    \bigwedge_{\boldsymbol{\eta}\in\Xi}
    \left[
        h_{\mathrm{plan}}
        \left(
            \boldsymbol{\lambda},
            \boldsymbol{\eta}
        \right)
        \leq h_{\max}
        \;\land\;
        I_{\mathcal{M}}
        \left(
            \boldsymbol{\lambda},
            \boldsymbol{\eta}
        \right)
        \in
        \mathcal{I}_{\mathrm{acceptable}}
    \right],
\end{equation}
with the required D0, D1, D4, D5, D6, and D7 planning obligations also
satisfied. A probabilistic robustness requirement may replace the conjunction
over $\Xi$, but its probability level and distribution must be declared.

Parameter selection may minimize total duration,
\begin{equation}
    \min_{\boldsymbol{\lambda}}
    T_{\mathrm{total}}
    \left(
        \boldsymbol{\lambda}
    \right),
\end{equation}
subject to adequacy and execution constraints. Alternatively, it may report a
Pareto set for coverage, informativeness, robustness, duration, and actuation
cost. An arbitrary weighted sum must not conceal important trade-offs.

When $\mathcal{F}$ is fixed, the problem asks whether that particular set of
trajectory families can be made adequate and which parameters provide the
best margins. When $\mathcal{F}$ is also variable, an outer comparison may
select among different protocol families. The same universal criteria are used
in both cases.

\subsection{Prospective Decision Semantics}

For criterion $k$, the prospective result is
\begin{equation}
    A_k^{\mathrm{plan}}
    \left(
        \Pi_{\boldsymbol{\lambda}}
        \mid
        \mathcal{T},
        \mathcal{H}
    \right)
    \in
    \left\{
        \textsc{Pass},
        \textsc{Fail},
        \textsc{Indeterminate},
        \textsc{Not Applicable}
    \right\}.
\end{equation}
Its interpretation is phase-qualified:
\begin{itemize}
    \item \textsc{Pass} means that the candidate protocol satisfies the
        declared prospective test over the declared uncertainty set. It does
        not imply an achieved-data pass.
    \item \textsc{Fail} means that a known violation exists for the candidate,
        or that a valid certificate or bound proves no allowed parameter vector
        can satisfy the requirement.
    \item \textsc{Indeterminate} means that required declarations or planning
        models are missing, uncertainty has not been treated adequately, or a
        search found no feasible candidate without proving infeasibility.
    \item \textsc{Not Applicable} requires the same explicit scientific
        justification as in the achieved phase.
\end{itemize}

Failure of a local or heuristic optimizer to find a feasible point is not, by
itself, evidence that a trajectory family is inadequate. Every result must
record the searched bounds, algorithm, initialization, stopping condition,
random seeds, uncertainty scenarios, and constraint margins.

The overall prospective result uses the same precedence rules as the achieved
assessment, but is reported as
\begin{equation}
    A_{\mathrm{plan}}
    \left(
        \Pi_{\boldsymbol{\lambda}}
        \mid
        \mathcal{T},
        \mathcal{H}
    \right)
\end{equation}
and must never be presented as
$A_{\mathrm{ach}}(D_{\mathrm{ach}}\mid\mathcal{T})$. Final adequacy requires
the achieved dataset and the retrospective criteria.

\section{Triaxial Force Sensor}

\subsection{General Triaxial Calibration Task}

For the triaxial sensor, the calibration task is defined as follows:
\begin{itemize}
    \item $\mathbf{s}$ is the sensor reading vector:
    \begin{equation}
        \mathbf{s}
        =
        \begin{bmatrix}
            c_1 & c_2 & c_3
        \end{bmatrix}^{\mathsf{T}},
    \end{equation}
    where $c_1$, $c_2$, and $c_3$ are the three raw coil signals.
    The vector $\mathbf{s}$ is the input of the calibration model.

    \item $\mathbf{q}$ is the reference force vector:
    \begin{equation}
        \mathbf{q}
        =
        \begin{bmatrix}
            F_x^{\mathrm{ref}} &
            F_y^{\mathrm{ref}} &
            F_z^{\mathrm{ref}}
        \end{bmatrix}^{\mathsf{T}},
    \end{equation}
    where the three force components are measured by the reference
    force/torque sensor. The vector $\mathbf{q}$ is the desired output of the
    calibration model and is used as the calibration target.

    \item $\Omega$ is the intended operating domain of the sensor. It defines
    the set of three-dimensional force vectors for which the calibration is
    expected to be valid:
    \begin{equation}
        \Omega
        =
        [F_x^{\min},F_x^{\max}]
        \times
        [F_y^{\min},F_y^{\max}]
        \times
        [F_z^{\min},F_z^{\max}]
        \subseteq \mathbb{R}^{3}.
    \end{equation}
    The force limits must be selected according to the intended application.

    \item $\mathcal{C}$ is the set of operating conditions that affect the
    sensor response and under which the calibration is expected to be valid:
    \begin{equation}
        \mathcal{C}
        =
        \mathcal{C}_{\mathrm{mount}}
        \times
        \mathcal{C}_{\mathrm{temperature}}
        \times
        \mathcal{C}_{\mathrm{rate}}.
    \end{equation}

    \item $\mathcal{M}$ is the calibration model or candidate model family. It
    defines the mappings considered for converting $\mathbf{s}$ into an
    estimated force vector $\widehat{\mathbf{q}}$:
    \begin{equation}
        \mathcal{M}
        =
        \left\{
            f_{\boldsymbol{\theta}} :
            \mathbf{s} \mapsto \widehat{\mathbf{q}}
            \;\middle|\;
            \boldsymbol{\theta} \in \Theta
        \right\},
    \end{equation}
    where $\boldsymbol{\theta}$ represents the model parameters and $\Theta$
    is their allowed parameter space.

    \item $\mathcal{P}$ is the set of required calibration-performance metrics
    and uncertainty limits. It contains the selected metrics and the
    application-specific thresholds that they must satisfy.

    \item $\mathcal{G}$ is the intended generalization claim. It defines the
    unseen runs, operating conditions, or physical sensor units for which the
    calibration is expected to remain valid:
    \begin{equation}
        \mathcal{G}
        \subseteq
        \mathcal{R}
        \times
        \mathcal{C}
        \times
        \mathcal{U},
    \end{equation}
    where $\mathcal{R}$ is the set of experimental runs, $\mathcal{C}$ is the
    set of operating conditions, and $\mathcal{U}$ is the set of physical
    sensor units.
\end{itemize}

\subsection{First Application: Affine Calibration Under Rigid Mounting}

\subsubsection{Declared Calibration Task}

The first application considers one individual triaxial sensor under rigid
mounting, using only its three sensing coils. The calibration task is
\begin{equation}
    \mathcal{T}_1
    =
    \left(
        \mathbf{s}_1,
        \mathbf{q}_1,
        \Omega_1,
        \mathcal{C}_1,
        \mathcal{M}_1,
        \mathcal{P}_1,
        \mathcal{G}_1
    \right).
\end{equation}

\begin{itemize}
    \item The sensor input and calibration target are
    \begin{equation}
        \mathbf{s}_1=\mathbf{s},
        \qquad
        \mathbf{q}_1=\mathbf{q}.
    \end{equation}

    \item $\Omega_1$ is the intended force domain for the first application.
    Its numerical force limits remain to be defined.

    \item $\mathcal{C}_1$ includes rigid mounting:
    \begin{equation}
        \mathcal{C}_1
        =
        \left\{\mathrm{rigid}\right\}
        \times
        \mathcal{C}_{\mathrm{temperature},1}
        \times
        \mathcal{C}_{\mathrm{rate},1}.
    \end{equation}
    The relevant temperature and loading-rate ranges remain to be defined.

    \item $\mathcal{M}_1$ is initially restricted to an affine memoryless
    calibration model:
    \begin{equation}
        \widehat{\mathbf{q}}
        =
        \mathbf{A}\mathbf{s}+\mathbf{b},
    \end{equation}
    where $\mathbf{A}\in\mathbb{R}^{3\times3}$ represents the sensor
    sensitivities and cross-axis relationships, and
    $\mathbf{b}\in\mathbb{R}^{3}$ represents the zero-force offsets. More
    complex model families will be considered only if simpler models are shown
    to be inadequate.

    \item $\mathcal{P}_1$ initially uses per-axis root-mean-square error and
    uncertainty. For validation sample $i$, the force-estimation error is
    \begin{equation}
        \mathbf{e}_i
        =
        \widehat{\mathbf{q}}_i-\mathbf{q}_i.
    \end{equation}
    For axis $j\in\{x,y,z\}$,
    \begin{equation}
        \operatorname{RMSE}_j
        =
        \sqrt{
            \frac{1}{N_{\mathrm{val}}}
            \sum_{i=1}^{N_{\mathrm{val}}}
            e_{i,j}^{2}
        },
    \end{equation}
    where $N_{\mathrm{val}}$ is the number of independent validation samples.
    The proposed form of the initial performance requirements is
    \begin{equation}
        \mathcal{P}_1
        =
        \left\{
            \operatorname{RMSE}_j \leq \varepsilon_j,
            \quad
            U_j \leq U_j^{\max}
            \;:\;
            j\in\{x,y,z\}
        \right\}.
    \end{equation}
    The numerical limits remain to be defined from the application
    requirements.

    \item $\mathcal{G}_1$ is generalization to new experimental runs of the
    same physical sensor under the declared operating conditions:
    \begin{equation}
        \mathcal{G}_1
        =
        \mathcal{R}_{\mathrm{new}}
        \times
        \mathcal{C}_1
        \times
        \left\{u_0\right\},
    \end{equation}
    where $u_0$ is the individual sensor being calibrated.
\end{itemize}

\subsubsection{Prospective Spiral--Lissajous Protocol Design}

The first protocol-design question is restricted to a declared collection of
spiral and Lissajous trajectory families:
\begin{quote}
Do there exist physically executable parameters for this collection such that
the protocol prospectively satisfies the applicable universal criteria for
$\mathcal{T}_1$?
\end{quote}
The trajectory families are application-specific. The adequacy obligations,
evidence levels, robustness requirements, and decision semantics used to
answer the question remain universal.

\paragraph{Normalized force coordinates.}
For force axis $j\in\{x,y,z\}$, define
\begin{equation}
    m_j
    =
    \frac{
        F_j^{\max}+F_j^{\min}
    }{2},
    \qquad
    r_j
    =
    \frac{
        F_j^{\max}-F_j^{\min}
    }{2},
\end{equation}
and represent a target force trajectory as
\begin{equation}
    q_j^{\mathrm{target}}(t)
    =
    m_j+r_j\xi_j(t),
    \qquad
    -1\leq\xi_j(t)\leq1.
\end{equation}
This normalization derives from the declared application domain; it must not
be estimated from a candidate or achieved trajectory. Joint excluded regions
and operating-condition constraints still apply after axis-wise
normalization.

\paragraph{Lissajous family.}
For Lissajous run $\ell$, one possible normalized parameterization is
\begin{equation}
    \xi_{j,\ell}^{\mathrm{Lis}}(t)
    =
    o_{j,\ell}
    +
    a_{j,\ell}
    \sin
    \left(
        2\pi n_{j,\ell}\frac{t}{T_\ell}
        +
        \phi_{j,\ell}
    \right),
    \qquad
    0\leq t\leq T_\ell,
\end{equation}
where $o_{j,\ell}$ is a normalized offset, $a_{j,\ell}$ is a normalized
amplitude, $n_{j,\ell}$ is a frequency-ratio parameter,
$\phi_{j,\ell}$ is a phase, and $T_\ell$ is the duration. At minimum,
\begin{equation}
    \left|o_{j,\ell}\right|
    +
    a_{j,\ell}
    \leq 1,
    \qquad
    a_{j,\ell}\geq0,
    \qquad
    n_{j,\ell}>0,
    \qquad
    T_\ell>0,
    \qquad
    0\leq\phi_{j,\ell}<2\pi,
\end{equation}
before joint-domain, safety, and rig constraints are applied.

For the corresponding target force,
\begin{align}
    \max_t
    \left|
        \dot{q}_{j,\ell}^{\mathrm{target}}(t)
    \right|
    &=
    \frac{
        2\pi r_j a_{j,\ell}n_{j,\ell}
    }{
        T_\ell
    },\\
    \max_t
    \left|
        \ddot{q}_{j,\ell}^{\mathrm{target}}(t)
    \right|
    &=
    r_j a_{j,\ell}
    \left(
        \frac{
            2\pi n_{j,\ell}
        }{
            T_\ell
        }
    \right)^2.
\end{align}
These relations connect amplitudes, frequency ratios, and duration to the
declared loading-rate and rig-dynamic constraints.

When all $n_{j,\ell}$ are integers, the geometric path is closed over its
fundamental period. Additional exact periods repeat the same static path and
do not automatically improve D2 coverage, although they may provide repeated
observations. Likewise, reversing time traverses the same static point set.
Forward/reverse runs are valuable for testing rate dependence, hysteresis, and
drift, but they do not constitute new memoryless domain coverage merely by
changing direction.

\paragraph{Spiral family.}
The term ``spiral'' is not a complete trajectory definition. Planar,
cylindrical, spherical, and volume-varying spirals cover different subsets of
the three-dimensional domain. For spiral run $p$, the application must declare
a specific normalized mapping
\begin{equation}
    \boldsymbol{\xi}_{p}^{\mathrm{Spi}}(t)
    =
    \mathbf{p}_{\mathrm{Spi}}
    \left(
        \frac{t}{T_p};
        \boldsymbol{\lambda}_{p}^{\mathrm{Spi}}
    \right),
    \qquad
    0\leq t\leq T_p,
\end{equation}
where
\begin{equation}
    \mathbf{p}_{\mathrm{Spi}}
    :
    [0,1]
    \times
    \Lambda_{\mathrm{Spi}}
    \longrightarrow
    [-1,1]^3.
\end{equation}
The declared parameter vector must identify the centre, radial law, angular
law, axial or polar progression, number of turns, duration, direction, and
boundary behavior as applicable. These choices are part of the triaxial
application, not universal constants.

\paragraph{Rig and sensor planning models.}
The target force paths do not imply that the rig can command force directly or
track them exactly. The rigid-rig adapter must map executable commands to
predicted achieved forces:
\begin{equation}
    \mathbf{q}^{\mathrm{pred}}_i
    =
    g_{1,\boldsymbol{\eta}}
    \left(
        \mathbf{u}_i,
        \mathbf{z}_i,
        \text{history}_i
    \right).
\end{equation}
If the rig is position- or displacement-controlled, an inverse or
trajectory-tracking method must generate $\mathbf{u}_i$ from the target-force
path. Its residual tracking error belongs in $\Xi_1$.

An initial affine sensor-response prior may be written as
\begin{equation}
    \mathbf{s}^{\mathrm{pred}}_i
    =
    \mathbf{H}_{\boldsymbol{\eta}}
    \mathbf{q}^{\mathrm{pred}}_i
    +
    \mathbf{d}_{\boldsymbol{\eta}}
    +
    \boldsymbol{\epsilon}_{i,\boldsymbol{\eta}},
\end{equation}
where the plausible sensitivity, cross-axis, offset, noise, temperature, and
rate effects are declared through $\boldsymbol{\eta}\in\Xi_1$. This prior may
come from physical design information, specifications, or separately
identified pilot evidence. It must not be represented as final calibration
evidence for the new sensor.

\paragraph{Prospective D2 calculation.}
For protocol parameter vector $\boldsymbol{\lambda}_1$ and scenario
$\boldsymbol{\eta}$, let
\begin{equation}
    \mathcal{Q}_{\mathrm{pred}}
    \left(
        \boldsymbol{\lambda}_1,
        \boldsymbol{\eta}
    \right)
    =
    \left\{
        \mathbf{q}^{\mathrm{pred}}_i,
        \mathbf{z}_i
    \right\}_{i=1}^{N_{\mathrm{pred}}}
\end{equation}
contain the union of all predicted runs. The prospective fill-distance
calculation is
\begin{equation}
    \widehat{h}_{\mathrm{plan}}
    \left(
        \boldsymbol{\lambda}_1,
        \boldsymbol{\eta}
    \right)
    =
    \max_{
        \mathbf{x}
        \in
        \Gamma_{\mathcal{X}_1,\mathrm{valid}}
    }
    \min_{
        \left(
            \mathbf{q}^{\mathrm{pred}}_i,
            \mathbf{z}_i
        \right)
        \in
        \mathcal{Q}_{\mathrm{pred}}
    }
    d_{\mathcal{X}_1}
    \left(
        \mathbf{x},
        \left(
            \mathbf{q}^{\mathrm{pred}}_i,
            \mathbf{z}_i
        \right)
    \right).
\end{equation}
It is evaluated jointly across forces and conditions after applying
predeclared exclusions. A collection of curves is not considered
space-filling merely because each force axis separately reaches its minimum
and maximum. Coverage must be reported for the complete protocol and for the
planned development and test partitions as required by D5 and D6; adequate
coverage of their union must not hide an unsupported partition.

\paragraph{Prospective D3 calculation.}
For the affine memoryless model, construct the predicted design matrix using
only samples assigned prospectively to development runs:
\begin{equation}
    \mathbf{X}_{1,\mathrm{dev}}^{\mathrm{pred}}
    \left(
        \boldsymbol{\lambda}_1,
        \boldsymbol{\eta}
    \right)
    =
    \begin{bmatrix}
        1 &
        \widetilde{c}^{\mathrm{pred}}_{1,1} &
        \widetilde{c}^{\mathrm{pred}}_{2,1} &
        \widetilde{c}^{\mathrm{pred}}_{3,1}\\
        \vdots & \vdots & \vdots & \vdots\\
        1 &
        \widetilde{c}^{\mathrm{pred}}_{1,N} &
        \widetilde{c}^{\mathrm{pred}}_{2,N} &
        \widetilde{c}^{\mathrm{pred}}_{3,N}
    \end{bmatrix}.
\end{equation}
The planned structural and conditioning requirements are
\begin{equation}
    \operatorname{rank}
    \left(
        \mathbf{X}_{1,\mathrm{dev}}^{\mathrm{pred}}
    \right)
    =4,
    \qquad
    \kappa
    \left(
        \mathbf{X}_{1,\mathrm{dev}}^{\mathrm{pred}}
    \right)
    \leq
    \kappa_{\max,1},
\end{equation}
under every required uncertainty scenario.

If only a force-space proxy is available, define
\begin{equation}
    \mathbf{X}_{q,1,\mathrm{dev}}^{\mathrm{pred}}
    =
    \begin{bmatrix}
        \mathbf{1} &
        \widetilde{\mathbf{F}}^{\mathrm{pred}}_{x} &
        \widetilde{\mathbf{F}}^{\mathrm{pred}}_{y} &
        \widetilde{\mathbf{F}}^{\mathrm{pred}}_{z}
    \end{bmatrix}.
\end{equation}
For the deterministic part of an affine sensor prior with nonsingular
$\mathbf{H}_{\boldsymbol{\eta}}$, there is an invertible augmented
transformation $\mathbf{B}_{\boldsymbol{\eta}}$ such that
\begin{equation}
    \mathbf{X}_{1,\mathrm{dev}}^{\mathrm{pred}}
    =
    \mathbf{X}_{q,1,\mathrm{dev}}^{\mathrm{pred}}
    \mathbf{B}_{\boldsymbol{\eta}}.
\end{equation}
The two matrices then have the same rank, so force-space rank provides a
structural proxy. Their condition numbers need not be equal. Force-space
conditioning alone therefore cannot establish robust coil-space
conditioning.

\paragraph{Joint parameter-selection problem.}
Let $\boldsymbol{\lambda}_1$ contain every spiral and Lissajous run parameter,
condition schedule, sampling choice, and repetition allocation. The runs are
optimized as one protocol, not as independently acceptable curves. One
possible formulation is
\begin{equation}
    \min_{\boldsymbol{\lambda}_1}
    T_{\mathrm{total}}
    \left(
        \boldsymbol{\lambda}_1
    \right)
\end{equation}
subject to
\begin{align}
    \boldsymbol{\lambda}_1
    &\in
    \Lambda_{1,\mathrm{safe}},\\
    \max_{\boldsymbol{\eta}\in\Xi_1}
    \widehat{h}_{\mathrm{plan}}
    \left(
        \boldsymbol{\lambda}_1,
        \boldsymbol{\eta}
    \right)
    &\leq
    h_{\max,1},\\
    \min_{\boldsymbol{\eta}\in\Xi_1}
    \operatorname{rank}
    \left(
        \mathbf{X}_{1,\mathrm{dev}}^{\mathrm{pred}}
        \left(
            \boldsymbol{\lambda}_1,
            \boldsymbol{\eta}
        \right)
    \right)
    &=4,\\
    \max_{\boldsymbol{\eta}\in\Xi_1}
    \kappa
    \left(
        \mathbf{X}_{1,\mathrm{dev}}^{\mathrm{pred}}
        \left(
            \boldsymbol{\lambda}_1,
            \boldsymbol{\eta}
        \right)
    \right)
    &\leq
    \kappa_{\max,1}.
\end{align}
The required D1 execution limits, D4 independent-run design, D5 partition,
D6 precision plan, and D7 provenance are additional constraints. A
multi-objective implementation may instead report nondominated trade-offs
among coverage, smallest singular value, conditioning, robustness, duration,
and actuation cost.

The currently discussed eight-run collection---two spiral directions and
three Lissajous phase configurations in forward and reverse directions---is a
candidate family set $\mathcal{F}_1$, not an adequacy conclusion. The first
search may hold this family set fixed and optimize its parameters. A later
outer comparison may evaluate alternative or hybrid families under the same
universal requirements.

\paragraph{Prospective conclusion and transition to acquisition.}
A parameterized spiral--Lissajous protocol receives a prospective
\textsc{Pass} only if it satisfies every applicable planning obligation over
the declared uncertainty treatment. It receives a prospective \textsc{Fail}
for a known violating candidate, or for the entire family only when valid
evidence proves that no parameter vector in the declared bounds can satisfy
the requirements. Failure of an optimizer to find a solution without such a
proof is \textsc{Indeterminate}.

The selected protocol, parameters, rig commands, uncertainty scenarios,
optimizer settings, seeds, planned run identities, and development/test
allocation must then be frozen and hashed. After acquisition, D1--D7 are
evaluated again using $D_{\mathrm{ach}}$. Differences between commanded,
predicted, and achieved trajectories become evidence about the protocol and
planning models rather than being hidden by the prospective conclusion.

\subsubsection{Application of D1}

For the first application, each calibration observation must contain the three
coil readings and the corresponding reference-force measurement:
\begin{equation}
    \mathbf{s}_i
    =
    \begin{bmatrix}
        c_{1,i} & c_{2,i} & c_{3,i}
    \end{bmatrix}^{\mathsf{T}},
    \qquad
    \mathbf{q}_i^{\mathrm{FT}}
    =
    \begin{bmatrix}
        F_{x,i}^{\mathrm{FT}} &
        F_{y,i}^{\mathrm{FT}} &
        F_{z,i}^{\mathrm{FT}}
    \end{bmatrix}^{\mathsf{T}}.
\end{equation}

The sensor and reference measurements must correspond to the same physical
state. Their synchronization error is
\begin{equation}
    \Delta t_i
    =
    t_i^{s}-t_i^{\mathrm{FT}},
\end{equation}
and must satisfy
\begin{equation}
    \lvert\Delta t_i\rvert\leq\Delta t_{\max}.
\end{equation}

The reference force must be expressed in the triaxial sensor coordinate frame:
\begin{equation}
    \mathbf{q}_i
    =
    \mathbf{R}_{\mathrm{FT}\rightarrow\mathrm{sensor}}
    \mathbf{q}_i^{\mathrm{FT}},
\end{equation}
where $\mathbf{R}_{\mathrm{FT}\rightarrow\mathrm{sensor}}$ is the known
coordinate transformation.

Every retained observation must satisfy
\begin{equation}
    \mathbf{s}_i\in\mathcal{S}_{\mathrm{valid}},
    \qquad
    \mathbf{q}_i^{\mathrm{FT}}\in\mathcal{Q}_{\mathrm{valid}},
\end{equation}
where $\mathcal{S}_{\mathrm{valid}}$ and $\mathcal{Q}_{\mathrm{valid}}$ are the
valid measurement ranges of the coil-acquisition system and reference F/T
sensor.

The reference uncertainty for each force axis must also satisfy
\begin{equation}
    U_j^{\mathrm{FT}}
    \leq
    U_j^{\mathrm{FT,max}},
    \qquad
    j\in\{x,y,z\},
\end{equation}
where the maximum acceptable reference uncertainty is determined from the
performance requirements $\mathcal{P}_1$.

Samples containing missing values, corrupted packets, clipping, or saturation
must be identified and excluded using a documented rule. The synchronization
tolerance, valid measurement ranges, coordinate transformation, and reference
uncertainty evidence remain to be defined from the acquisition-system and
reference specifications. The maximum acceptable reference uncertainty is a
separate application requirement derived from the calibration uncertainty
budget.
\subsubsection{Application of D2}

For the first application, the intended three-dimensional force domain is
\begin{equation}
    \Omega_1
    =
    [F_x^{\min},F_x^{\max}]
    \times
    [F_y^{\min},F_y^{\max}]
    \times
    [F_z^{\min},F_z^{\max}].
\end{equation}

Only samples that satisfy D1 are used. Their achieved reference-force vectors
form the set
\begin{equation}
    \mathcal{S}_{D_1}
    =
    \left\{
        \mathbf{q}_i
        =
        \begin{bmatrix}
            F_{x,i}^{\mathrm{ref}} &
            F_{y,i}^{\mathrm{ref}} &
            F_{z,i}^{\mathrm{ref}}
        \end{bmatrix}^{\mathsf{T}}
        :
        i\in\mathcal{I}_{\mathrm{valid}}
    \right\},
\end{equation}
where $\mathcal{I}_{\mathrm{valid}}$ is the set of samples accepted by D1.

The normalized distance in the triaxial force domain is
\begin{equation}
    d_{\Omega_1}(\mathbf{F},\mathbf{q}_i)
    =
    \sqrt{
        \left(
            \frac{F_x-F_{x,i}^{\mathrm{ref}}}
                 {F_x^{\max}-F_x^{\min}}
        \right)^2
        +
        \left(
            \frac{F_y-F_{y,i}^{\mathrm{ref}}}
                 {F_y^{\max}-F_y^{\min}}
        \right)^2
        +
        \left(
            \frac{F_z-F_{z,i}^{\mathrm{ref}}}
                 {F_z^{\max}-F_z^{\min}}
        \right)^2
    }.
\end{equation}

Because the continuous domain cannot be checked directly, it is approximated
using a sufficiently dense evaluation grid
$\Gamma_{\Omega_1}\subset\Omega_1$. The estimated fill distance is
\begin{equation}
    \widehat{h}(D_1,\Omega_1)
    =
    \max_{\mathbf{F}\in\Gamma_{\Omega_1}}
    \min_{\mathbf{q}_i\in\mathcal{S}_{D_1}}
    d_{\Omega_1}(\mathbf{F},\mathbf{q}_i).
\end{equation}

The first dataset satisfies D2 when
\begin{equation}
    \widehat{h}(D_1,\Omega_1)
    \leq
    h_{\max,1}.
\end{equation}

The declared operating conditions must also be supported. Let
\begin{equation}
    \mathcal{S}_{\mathcal{C}_1}
    =
    \left\{
        \mathbf{z}_i
        :
        i\in\mathcal{I}_{\mathrm{valid}}
    \right\}.
\end{equation}
For a condition held fixed, such as rigid mounting,
$\mathcal{C}_{\mathrm{mount},1}$ is a singleton. Any claimed temperature or
loading-rate range must be represented by
$\mathcal{S}_{\mathcal{C}_1}$ or explicitly excluded from the first claim.

The force limits, evaluation-grid resolution, and maximum acceptable fill
distance $h_{\max,1}$, together with the claimed condition ranges, must be
declared before assessing the collected trajectories.
\subsubsection{Application of D3}

For the first application, the declared model is the affine calibration
\begin{equation}
    \widehat{\mathbf{q}}_i
    =
    \mathbf{A}\mathbf{s}_i+\mathbf{b},
\end{equation}
where $\mathbf{A}\in\mathbb{R}^{3\times3}$ and
$\mathbf{b}\in\mathbb{R}^{3}$. The model therefore contains twelve parameters.

Before evaluating conditioning, each coil signal is normalized:
\begin{equation}
    \widetilde{c}_{k,i}
    =
    \frac{
        c_{k,i}-c_k^{\mathrm{mid}}
    }{
        \left(c_k^{\max}-c_k^{\min}\right)/2
    },
    \qquad
    c_k^{\mathrm{mid}}
    =
    \frac{c_k^{\min}+c_k^{\max}}{2},
\end{equation}
for $k\in\{1,2,3\}$.

For each calibration sample, define the feature vector
\begin{equation}
    \boldsymbol{\phi}_i
    =
    \begin{bmatrix}
        1 &
        \widetilde{c}_{1,i} &
        \widetilde{c}_{2,i} &
        \widetilde{c}_{3,i}
    \end{bmatrix}^{\mathsf{T}}.
\end{equation}

The design matrix constructed from the samples accepted by D1 is
\begin{equation}
    \mathbf{X}_1
    =
    \begin{bmatrix}
        \boldsymbol{\phi}_1^{\mathsf{T}}\\
        \boldsymbol{\phi}_2^{\mathsf{T}}\\
        \vdots\\
        \boldsymbol{\phi}_{N_{\mathrm{fit}}}^{\mathsf{T}}
    \end{bmatrix}
    \in
    \mathbb{R}^{N_{\mathrm{fit}}\times4}.
\end{equation}

Writing
\begin{equation}
    \mathbf{B}
    =
    \begin{bmatrix}
        \mathbf{b} & \mathbf{A}
    \end{bmatrix}
    \in\mathbb{R}^{3\times4},
\end{equation}
the predicted force matrix is
\begin{equation}
    \widehat{\mathbf{Q}}
    =
    \mathbf{X}_1\mathbf{B}^{\mathsf{T}}.
\end{equation}

For the three-output affine model, the full sensitivity matrix is
\begin{equation}
    \mathbf{J}_{D_1}
    =
    \mathbf{I}_3\otimes\mathbf{X}_1,
\end{equation}
where $\otimes$ denotes the Kronecker product. Therefore,
\begin{equation}
    \operatorname{rank}(\mathbf{J}_{D_1})
    =
    3\operatorname{rank}(\mathbf{X}_1).
\end{equation}

All twelve affine-model parameters are identifiable if and only if
\begin{equation}
    \operatorname{rank}(\mathbf{X}_1)=4.
\end{equation}

The practical conditioning of the calibration is
\begin{equation}
    \kappa(\mathbf{X}_1)
    =
    \frac{\sigma_{\max}(\mathbf{X}_1)}
         {\sigma_{\min}(\mathbf{X}_1)}.
\end{equation}

The first dataset satisfies D3 for the affine model when
\begin{equation}
    \operatorname{rank}(\mathbf{X}_1)=4,
    \qquad
    \kappa(\mathbf{X}_1)
    \leq
    \kappa_{\max,1}.
\end{equation}

The numerical rank tolerance and maximum acceptable condition number
$\kappa_{\max,1}$ must be declared before evaluating the candidate calibration
trajectories.

\subsubsection{Application of D4}

For the first triaxial calibration, the dataset is divided into independent
experimental runs:
\begin{equation}
    D_1
    =
    \bigcup_{r=1}^{R_1}D_{1,r},
\end{equation}
where $D_{1,r}$ contains the D1-valid samples collected during run $r$.

An independent run is a separately executed experiment with a new acquisition
start and the declared initialization and zeroing procedure. Dividing one
continuous recording into several segments does not create independent runs.

The signals considered when evaluating temporal dependence are
\begin{equation}
    \mathcal{V}_1
    =
    \left\{
        c_1,c_2,c_3,
        F_x^{\mathrm{ref}},
        F_y^{\mathrm{ref}},
        F_z^{\mathrm{ref}}
    \right\}.
\end{equation}

For each signal $v\in\mathcal{V}_1$, the effective sample size is estimated as
\begin{equation}
    N_{\mathrm{eff},v}^{(1)}
    =
    \sum_{r=1}^{R_1}
    \frac{N_r}
    {
        1
        +
        2\sum_{k=1}^{K_v}\rho_{r,v}(k)
    },
\end{equation}
where $N_r$ is the number of valid samples in run $r$.

If the protocol contains different trajectory configurations indexed by
$\ell$, the number of independent runs for configuration $\ell$ is
\begin{equation}
    R_{1,\ell}
    =
    \left|
        \left\{
            r :
            \text{run }r\text{ uses configuration }\ell
        \right\}
    \right|.
\end{equation}

The first dataset satisfies D4 when
\begin{equation}
    R_1\geq R_{\min,1},
    \qquad
    R_{1,\ell}\geq R_{\min,\ell},
    \qquad
    \min_{v\in\mathcal{V}_1}
    N_{\mathrm{eff},v}^{(1)}
    \geq
    N_{\mathrm{eff},1}^{\min}.
\end{equation}

The minimum number of independent runs, required repetitions per trajectory
configuration, autocorrelation lag, and minimum effective sample size remain to
be declared.

\subsubsection{Application of D5}

For the first application, the declared generalization target is new runs of
the same physical sensor under the conditions $\mathcal{C}_1$. Therefore, the
independent validation unit is the complete experimental run.

Let $\mathcal{R}_1$ be the set of recorded runs. It is divided into
development and test runs:
\begin{equation}
    \mathcal{R}_1
    =
    \mathcal{R}_{\mathrm{dev}}
    \;\dot{\cup}\;
    \mathcal{R}_{\mathrm{test}},
\end{equation}
with
\begin{equation}
    \mathcal{R}_{\mathrm{dev}}
    \cap
    \mathcal{R}_{\mathrm{test}}
    =
    \varnothing.
\end{equation}

The corresponding datasets are
\begin{equation}
    D_{\mathrm{dev}}
    =
    \bigcup_{r\in\mathcal{R}_{\mathrm{dev}}}D_{1,r},
    \qquad
    D_{\mathrm{test}}
    =
    \bigcup_{r\in\mathcal{R}_{\mathrm{test}}}D_{1,r}.
\end{equation}

The affine calibration parameters are estimated using only the development
runs:
\begin{equation}
    \left(
        \widehat{\mathbf{A}},
        \widehat{\mathbf{b}}
    \right)
    =
    \arg\min_{\mathbf{A},\mathbf{b}}
    \sum_{i\in D_{\mathrm{dev}}}
    \left\|
        \mathbf{A}\mathbf{s}_i
        +
        \mathbf{b}
        -
        \mathbf{q}_i
    \right\|_2^2.
\end{equation}

For each test sample, the predicted force and error are
\begin{equation}
    \widehat{\mathbf{q}}_i
    =
    \widehat{\mathbf{A}}\mathbf{s}_i
    +
    \widehat{\mathbf{b}},
    \qquad
    \mathbf{e}_i
    =
    \widehat{\mathbf{q}}_i-\mathbf{q}_i.
\end{equation}

The final per-axis RMSE is calculated only on the held-out runs:
\begin{equation}
    \operatorname{RMSE}_{j,\mathrm{test}}
    =
    \sqrt{
        \frac{1}{N_{\mathrm{test}}}
        \sum_{i\in D_{\mathrm{test}}}
        e_{i,j}^{2}
    },
    \qquad
    j\in\{x,y,z\}.
\end{equation}

The first application satisfies D5 when
\begin{equation}
    \mathcal{R}_{\mathrm{dev}}
    \cap
    \mathcal{R}_{\mathrm{test}}
    =
    \varnothing,
    \qquad
    \left|\mathcal{R}_{\mathrm{test}}\right|
    \geq
    R_{\mathrm{test}}^{\min},
\end{equation}
and the test runs have not been used for preprocessing, model selection,
parameter estimation, or threshold selection.

\subsubsection{Application of D6}

For the first application, performance is evaluated separately for each force
axis using the held-out runs defined by D5. The test error is
\begin{equation}
    e_{i,j}
    =
    \widehat{q}_{i,j}-q_{i,j},
    \qquad
    j\in\{x,y,z\}.
\end{equation}

The estimated per-axis performance is
\begin{equation}
    \widehat{\operatorname{RMSE}}_{j,\mathrm{test}}
    =
    \sqrt{
        \frac{1}{N_{\mathrm{test}}}
        \sum_{i\in D_{\mathrm{test}}}
        e_{i,j}^{2}
    }.
\end{equation}

Because samples within a run are correlated, confidence intervals are
estimated by resampling complete test runs rather than individual samples.
For bootstrap repetitions $b=1,\ldots,B$, let
$\widehat{\operatorname{RMSE}}_{j}^{(b)}$ be the metric calculated after
resampling the runs in $\mathcal{R}_{\mathrm{test}}$. A
$(1-\alpha)$ confidence interval is
\begin{equation}
    CI_{j,1-\alpha}
    =
    \left[
        Q_{\alpha/2}
        \left(
            \left\{
                \widehat{\operatorname{RMSE}}_{j}^{(b)}
            \right\}_{b=1}^{B}
        \right),
        Q_{1-\alpha/2}
        \left(
            \left\{
                \widehat{\operatorname{RMSE}}_{j}^{(b)}
            \right\}_{b=1}^{B}
        \right)
    \right],
\end{equation}
where $Q_p$ denotes the empirical $p$-quantile. Let
$\operatorname{RMSE}_{j}^{-}$ and $\operatorname{RMSE}_{j}^{+}$ denote the
lower and upper bounds of this interval. Its half-width is
\begin{equation}
    w_j
    =
    \frac{
        \operatorname{RMSE}_{j}^{+}
        -
        \operatorname{RMSE}_{j}^{-}
    }{2}.
\end{equation}

The first dataset provides sufficiently precise performance evidence when
\begin{equation}
    w_j\leq w_j^{\max},
    \qquad
    j\in\{x,y,z\}.
\end{equation}

The affine calibration satisfies the initial RMSE requirement when
\begin{equation}
    \operatorname{RMSE}_{j}^{+}
    \leq
    \varepsilon_j,
    \qquad
    j\in\{x,y,z\}.
\end{equation}

To detect local failure hidden by a global RMSE, the same metrics are reported
over predeclared regions
$\{\mathcal{B}_{1,b}\}_{b=1}^{B_1}$ of the supported force and condition
domain:
\begin{equation}
    \operatorname{RMSE}_{j,b}
    =
    \sqrt{
        \frac{1}{N_b}
        \sum_{
            i\in D_{\mathrm{test}}
            :
            (\mathbf{q}_i,\mathbf{z}_i)\in\mathcal{B}_{1,b}
        }
        e_{i,j}^{2}
    }.
\end{equation}

The calibrated-force uncertainty $U_j$ must also be estimated using a declared
uncertainty model and satisfy
\begin{equation}
    U_j\leq U_j^{\max},
    \qquad
    j\in\{x,y,z\}.
\end{equation}
The confidence level, number of bootstrap repetitions, maximum interval
half-widths, RMSE thresholds, and uncertainty-estimation method remain to be
declared.

\subsubsection{Application of D7}

For the first application, the reproducibility package must contain:
\begin{itemize}
    \item the exact spiral and Lissajous family definitions, parameter bounds,
        selected parameters, condition schedules, and generated rig commands;
    \item the rig and sensor planning models, their evidence sources,
        uncertainty scenarios, and constraint definitions;
    \item the optimizer implementation, objectives, initializations, stopping
        conditions, random seeds, candidate results, feasibility margins, and
        any claimed infeasibility certificate;
    \item the immutable raw coil, reference F/T, timestamp, and run metadata;
    \item a SHA-256 manifest for every raw and configuration file;
    \item the sensor, reference instrument, rig, and acquisition profiles;
    \item the declared task $\mathcal{T}_1$ and all D1--D6 parameters;
    \item the preprocessing operations and excluded-sample records;
    \item the development and test run identifiers;
    \item the software version, source-control commit, dependencies, and random
        seeds; and
    \item the generated prospective and achieved criterion metrics, outcomes,
        diagnostic figures, and commanded--predicted--achieved comparisons.
\end{itemize}

Let $\mathcal{E}_1$ denote this evidence package. The first application
satisfies D7 when an independent execution using $\mathcal{E}_1$ reproduces
the prospective parameter-selection results and the achieved D1--D6 outcomes
and numerical results within the declared numerical tolerances. Missing
planning assumptions, raw data, unresolved file-integrity changes, or
undocumented preprocessing make the assessment non-reproducible.
